# Autonomous Repository Upgrade

Autonomy does not imply unlimited authority.

Inspect instructions, Git state, architecture, dependencies, CI, tests, security tooling, deployment, infrastructure, docs, issues, PRs and release process.

Prioritize P0 security/data/release blockers, P1 reliability/CI/restore/rollback/auth gaps, P2 observability/automation/performance/maintainability and P3 optional improvements.

Work in small reviewable waves with baseline, minimal change, validation, security review and evidence. Do not mass-upgrade or redesign without a demonstrated need.

Stop on secrets, uncertain production state, destructive operations, irreversible migrations, user-data risk, instruction conflicts or insufficient permissions.
